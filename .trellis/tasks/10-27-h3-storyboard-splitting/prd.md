# H3 分镜格式与约五秒片段拆分

## 目标与用户授权

用户希望 AI 拆分镜直接产出 H3 适用提示词，单次生成片段尽量约 5 秒，并在依据充分时按帧率计算时间，减少手动改格式和切段。

第一轮用户批准“未选模型时默认写 H3 格式，不新增选择器、不自动选供应商或启动生成”，仅限入口请求与对应测试；已随 `0cb0c8a` 完成并通过独立检查。

第二轮用户已明确收窄为“先更新到中文的符合 H3 的格式”，以便直接阅读和编辑。此前讨论的自动素材绑定、关键帧准备及连续生成不进入本轮。用户在审阅三份文件的最小方案与版本风险后回复“行”，明确批准保留 H3 字段和固定标记、将正文及示例改为中文，并把“剧本制片”由 v1 升为 v2。官方与源码证据见 `research/chinese-prompt-followup.md`。

## 背景事实

- 桌面拆分按钮向聊天填入请求，用户自行发送；第一轮已修正此前无条件要求通用 Shot 的文案，当前加载 H3 附件的路由位于 `lib/desktop/features/storyboard/region.dart:389–402`。人工发送边界见 `lib/desktop/pages/novel_editor.dart:4548–4559`。
- 制片 Skill 已具备完整正文覆盖、连续性、模型适配和 H3 专用格式，不需要重写方法或增加独立 splitter。真源见 `research/method-boundaries.md`。
- 当前 H3 渠道包含 5 秒能力，但接口不提供输出 fps、帧数或步长参数；生成还要求整秒。输入视频的 fps 范围不是输出帧率。证据见 `research/runtime-constraints.md` 与 `lib/shared/services/production/generate_orchestrator.dart:235–241`。
- 未发现移动端对应拆分按钮；移动端普通聊天不在本次入口改动范围内，不新增移动页面。

## 需求

### R1 — 专用格式优先

拆分请求应显式引导读取既有制片流程、分镜方法和适用的视频格式。用户明确目标为 H3，或当前所选模型可识别为 H3 及其渠道别名时，加载既有 H3 附件并按实际输入条件编写，不能再被通用 Shot 要求覆盖。不擅自切换已选非 H3 模型；型号未确定且用户未指定时默认按 H3 格式写草稿，但不自动选择或填写供应商/模型配置，也不能声称已配置 H3。

### R2 — 约五秒且能衔接

以每个可独立生成的视频片段约 5 秒为优先目标，而不是每个叙事场次或每行对白 5 秒。使用模型接受的合法时长；完整对白、动作阶段和连续性优先，装不下时在合理切点拆开或说明延长原因，不能加速表演、删戏、重演动作或机械逐行切分。其他型号保留自身格式及能力约束，不强制改成 H3。

### R3 — 帧率辅助规划，不伪造输出控制

真实输出 fps 和帧数约束已知时，按这些依据换算帧数与时间，核对切点与计划总长；不得把参考输入的 fps 上限当输出 fps，不硬编码 24 fps、120 帧或某个外部工作流的步长。未知时标明未校准。当前应用仍按合法整秒提交；外部帧数规则与此不兼容时说明差异，不写入不受支持的小数秒并声称可生成，不假装已传递帧数参数。

### R4 — 范围与数据保护

读取目标场次完整正文及当前集已有分镜，以真实人物、地点、逐字对白和状态为依据。后续用户实际调用拆分时，已有同内容条目按授权范围修订，不盲目新增副本。开发期间不操作用户剧本、分镜或媒体；按钮仍只填入聊天请求，不自动发送、生成或采用结果。

### R5 — H3 中文可读正文（第二轮）

H3 提示词默认使用中文描述画面、动作、声音、参考用途、保留关系和衔接；对白、歌词与画面文字保持来源原文。保留三个／六个核心字段的名称和顺序、Shot 与切点时间格式、首尾帧对齐模板、素材引用和说话／台词标签，不改成另一套生成模式。去除附件内相互矛盾的英文正文要求和英文词数配额，提供三段及全参考六段的中文内容示例。补充官方来源，明确这是保留官方结构的中文适配，不声称与官方英文改写要求完全相同或成片质量等价。不新增 i18n、界面语言切换逻辑或全局翻译层。

### R6 — 更新能沿用既有安装机制（第二轮）

仅更新“剧本制片”的内容元数据和必要测试，保留身份、附件路径与用户自定义／停用／删除语义。不以 hash 测试代替发布状态核查，不新增运行时 fallback 或快照兼容层，不直接修改业务及 Debug/Release 数据库。本地缺少正式发布 tag，当前 version=1 的发布状态不能核实；用户已明确批准本次升 version=2，以走既有官方升级流程。该决定不等于认定 v1 已发布或未发布。

## 验收标准

- A1（R1）：真实点击拆分按钮触发的请求包含正确场次路径、现有方法与 H3 条件路由，不再无条件要求通用 Shot；模型未定与非 H3 场景均有明确边界。
- A2（R2）：请求明确约 5 秒是片段偏好而非硬性配额，并保留完整内容、合理拆分与连续性要求。
- A3（R3）：请求包含已知 fps 才换算、未知不猜、整秒提交及不冒充精确帧控制的边界。原有能力与生成验证不改。
- A4（R4）：点击只调用聊天请求回调，不新增或修改测试库分镜；真实界面仍为人工发送。原有列表刷新、删除确认和软删除回归保留。
- A5：目标 widget 整文件测试、窄范围静态分析、格式与 diff 检查通过；独立审查确认只修改批准的入口与测试。自动测试仅证明请求契约，不证明真实 H3 输出质量或精确帧数。
- A6（R5）：通过真实附件加载核对三段和六段的中文规则与示例、字段顺序及关键标记，确认旧英文强制要求和英文词数配额不再与中文规则冲突；不据此声称真实 Agent 一定遵从。
- A7（R6）：用户确认版本处理后，版本／hash／updatedAt 一致；官方技能加载、打包、链接、内容指纹及既有升级测试串行通过。共享附件覆盖桌面和移动端，非 H3 附件和实际媒体生成不改；不声称用户设备已安装快照已经升级。

## 非目标

- 地点/地图出图、人物四视图、资源提取、自动图片绑定、画布布局或连线。
- 第一轮未修改任何 Skill。第二轮仅拟修改现有 H3 附件、“剧本制片”的注册元数据及现有加载测试；其他 Skill 正文／附件、通用 Agent 提示词、工具 description/schema、视频 API、模型目录、数据库 schema、帧率 UI 或 H3 部署不改。
- 真实生成、付费调用、Debug/Release 数据库修改、批量重写已有分镜或原文。
- 自动把模型配置改成 H3、所有模型强制五秒、逐帧描述或新增移动拆分功能。默认 H3 仅适用于未选模型时的提示词格式。

## 决策与风险

- 第一轮采用既有拆分请求＋现有 widget 测试的最小改法，未修改 Skill。第二轮中文化的真源是 H3 附件，不把模板或覆盖规则复制到拆分 UI；用户已单独批准 v1→v2，不沿用此前剧本写作任务的版本例外。
- 帧数仅作为有依据的规划校核；本次不扩展后端帧参数。实际输出 fps/帧数需要另行运行验证，不是此任务验收承诺。
- 模型可能不遵循请求，用户自定义/禁用的技能也可能影响行为；保留现有选择语义，不能靠本次静态测试宣称已解决实际成片质量。
