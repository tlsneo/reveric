# H3 拆分镜设计

前两轮已交付，下面说明保留为历史边界。当前只实施末尾第三轮「H3 可拍分镜与全参考成稿」，用户已批准五文件最小范围及 v2→v3；第二轮中文格式和媒体边界继续保留。

## 第一轮变更边界

产品文件仅两个：

1. `lib/desktop/features/storyboard/region.dart`：只替换 `_SceneHeader.onSplit` 向 `sceneActions.ask` 传入的请求文字；不改布局、状态、回调协议、选中模型或服务调用。
2. `test/desktop/features/storyboard/region_test.dart`：在现有真实组件测试中注入 `ProductionSceneActions`、收集请求并点击拆分按钮；补充语义断言和点击不写分镜的断言。保留原有刷新/删除回归与清理机制。测试职责变化时更新文件头。

复用当前链路：

```text
场次拆分按钮 → sceneActions.ask → 现有聊天草稿（人工发送）
→ 通用 Agent → 既有剧本制片/剧本工具使用规范 → 原有分镜操作
```

不新增函数、服务、模型字段、设置项或 Skill；不把 H3 字段模板复制进 UI。

## 请求应表达的完整任务

按以下顺序组织为一份共用中文请求，不做 i18n：

1. 用点击的 `/scenes/{id}` 明确范围，完整读取其 `/elements`、角色与地点，并读取当前集已有分镜，避免拿场次 metadata 代替正文或重复新增。
2. 加载“剧本制片”的制片流程、分镜指南、模型能力、视频提示词；写入前遵循“剧本工具使用规范”的分镜与媒体节点附件。逐项执行前取得所需规则即可，不要求预读所有媒体方法。
3. 沿用已选型号，或尊重用户已明确指定的目标；H3/其已识别渠道别名明确加载 `minimax-h3-prompts.md`，按真实绑定输入使用其格式；其他模型用其对应格式。用户批准未选模型且未指定目标时也默认使用 H3 提示词格式，但不自动填入供应商/型号或声称配置就绪。这是本任务的显式请求偏好，覆盖通用附件在未选模型时的通用格式默认，不改附件本身。提示词方法仍由附件拥有。
4. 每个视频片段优先约 5 秒，实际时长须合法；关键对白、动作阶段和前后状态不能为时长而删减或加速，在可剪辑边界拆开，必要延长要说明。不要要求五秒塞入多个复杂镜头。
5. 真实输出 fps 与合法帧数约束已知时用它们校核时间与切点；不知道就说明未校准。不把参考输入 fps 范围当输出 fps，不猜固定数值。不兼容现有整秒提交的外部帧数计划需说明，不伪造可执行配置或帧控制。
6. 写入本场分镜，保护原文及未改内容、保留/复用已有条目与真实引用，回读场次归属、顺序、计划时长和相邻状态；只完成拆分草稿，不自动生成媒体。

上述文字是调用任务的范围、偏好和证据要求，不是新的模型输出格式或工具参数定义。文字可适度压缩，但不得删掉 PRD 的边界。

## 时长契约

- 本地实际 H3 渠道支持 5 秒；仍以用户配置的渠道和查询结果为准。
- `duration_ms` 是保存的计划值，生成要求 `% 1000 == 0`。本次不修改此约束。
- N/fps 可作为已知外部条件下的规划校核，不等于生成请求支持 N 或 fps 字段；不得自动把 5.166… 秒写成生成就绪配置。
- 若用户没有提供可信 fps，维持可提交的约 5 秒计划并明确未按帧校准，不为获取它要求用户完成新的配置流程。
- 不将导演台时间轴 fps 或参考视频 fps 混同目标模型输出 fps。

## 跨平台与兼容

桌面 Windows/macOS 共用同一请求；不调整窗口布局。移动端未发现对应拆分按钮，不新增入口，也不声称改变其普通聊天行为。现有用户点击后人工发送、自定义/禁用 Skill、所有模型配置与媒体输入语义保持。

用户已批准上述默认 H3 的格式选择及不新增选择器的最小方案。只改调用请求，不修改官方 Skill 资源与元数据。无本地正式 tag 不能证明未发布，但本方案无需版本维护决策。若实施中发现必须改 Skill、其他产品文件或后端，应停回规划，不自行扩展。

## 取舍与回滚

选择入口请求修正而不是新增确定性分镜流水线：原有方法已存在，缺口是入口指令冲突及本次短片段偏好未传达。代价是仍依赖 Agent 遵循；本次不承诺硬运行门禁或生成质量。

回滚只撤销第一轮的两个产品文件改动，不回滚他人改动、不操作用户数据、不改 Skill 安装快照。没有数据库迁移、部署或外部系统状态变更。

## 第二轮：中文正文（已批准）

1. `assets/official_skills/screenplay-production/references/minimax-h3-prompts.md`：H3 描述正文与示例默认中文，保留既有结构、字段与固定语法；同时清除 summary、detailed_description、英文词数建议和示例中的语言冲突。补充简短官方来源及中文适配说明，三段和六段均有可读示例。

复用“入口加载 H3 附件 → Agent 按附件写分镜”的现有链路，不再修改拆分按钮、UI、模型选择、生成服务或输入适配。共享附件同时面向桌面和移动端调用；其他模型的语言建议保持。

### 保留与修改

- 保留三段／六段字段顺序，`[Shot N]`、切点格式、固定首尾帧对齐模板、`<ref …/>`、`<Subject N>`、`(S1)`、`<d>[Chinese] …</d>`、`<scenetrans>`、`<cutoff>`、关系标记和 `N/A` 等语法。
- 画面、动作、声音、主体定义与参考保留解释使用中文；固定模板旁说明其用途，避免用户需要编辑整段英文叙述。原始台词、歌词及可见文字不翻译。
- 不将“350–500 英文词”机械换算成中文字数，不因配额删减对白和动作。
- 中文是官方云 API 的合法输入；本项目选择中文正文并保留官方结构，不宣称逐条遵循官方英文改写指南，也不承诺效果等价。

### 发布状态与安装

证据见 `research/chinese-prompt-followup.md`：本地没有正式 tag，不能据此判断 v1 未发布。用户在获知不确定性后明确批准本轮升至 v2，以既有 version 比较升级官方安装；不改同步逻辑，不为本轮增加 hash fallback，不直接改 Debug/Release 数据库。不能据源码更新声称用户设备已生效。

### 不做与回滚

## 第三轮：H3 可拍分镜与全参考成稿

用户已明确批准本轮，细则以 `research/h3-shot-quality-followup.md` 为准。仅五文件：现有 `screenplay-production/SKILL.md`、`references/production.md`、`references/shot-recipes.md`、`bundled_official_skills.dart`、`bundled_official_skills_test.dart`。

- 主入口把镜头设计和逐 Shot 核对接进必经流程，详细标准由 production 附件拥有；不复制完整 H3 语法到主文，不改变 when_to_use/description 或工具 schema。
- production 中先按原事件确定镜头职责、取景/机位、动作过程、摄影机变化与时长，再调用已有 H3 格式，写后检查可见结束和真实引用。计划不是新资源，也不是要塞进 H3 prompt 的通用外壳。
- shot-recipes 保留旧四例并追加屏幕/键盘操作例：坏摘要→可拍计划→明确为教学假设的 H3 六段中文成稿→验收。8 秒仅示例，不作为新默认；不凭空编造已绑定素材。格式继续由现有 H3 附件定义，本轮不重写该附件。
- 对用户明确的全参考目标，缺图时只交带状态说明的可拍草稿，不自动改目标或捏造引用；正常其他模式和模型保持。
- 只将剧本制片升 v3、按现有算法更新 hash/date；本地无正式 tag、发布未知已披露，本轮用户另行批准版本处理。不写运行时 fallback，不改同步器或安装库。

复用原 Agent→Skill→现有分镜工具链，不增加服务、UI、自动绑图或生成；共享文本面向桌面/移动端，不改既有业务分镜。测试只证明文本/打包/升级，不保证模型遵循或实际成片。
