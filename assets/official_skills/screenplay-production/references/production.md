# 剧本制片

## 制作单位与操作边界

界面的“分镜”是场次下的一条制作内容，一次生成可含一个或多个 Shot 镜头；“视频”是独立制作节点，不自动进入成片。用户说“改第几个分镜”时先定位该条内容；说“改 Shot 2”时只修改其提示词中的对应镜头，不另建分镜。

制作设置、场次归属、排序、素材输入、生成、采用与导出遵循「剧本工具使用规范」对应附件。本附件只负责制作安排。画布位置不代表播放顺序，导演台布景也不等于已生成视频。

分镜提示词与剧本正文分别维护。仅调整镜头表达时保留原事件、人物关系与逐字对白；确需改剧情或台词时，按用户授权修改对应原文，再同步受影响分镜。

## 从场次拆分镜

1. 读取目标场次的实际正文、必要人物与地点信息，以及当前集已有片段。已有同内容片段时原地修订，避免每次拆分都重复创建。
2. 梳理原文事项与戏剧变化：按原文顺序列出必须保留的动作、逐字对白、揭示和转折，明确本场从什么状态变到什么状态、观众何时获知信息。此时不预先分配给片段，不按行数或时长框切条目；先理解整场，再设计承担这些变化的镜头。
3. 形成可拍镜头计划与表演预算，再决定分组：每个 Shot 先明确观众要看见的变化；据此确定景别、机位朝向、画内主体的位置与起点，再写从起点到终点的可见过程。手部、道具、屏幕与文字等关键细节必须在取景中可辨认，不能用剧情摘要代替拍法。固定镜头合法；换视角时明确切镜，或从哪里向哪里移动、如何停下的连续运镜，写有用的方向、速度或停点，不写含糊的“画面转向”。声音按画内动作声、画外声、对白与配乐分清。具体设计见 [分镜指南](storyboard.md)，常见难点见 [镜头任务配方](shot-recipes.md)。
   - 对每个不可逆动作记录“前态 → 唯一执行 Shot → 后态”，如压盖、递盒、开盖、取物各自在何处实际发生；后续镜头承接已完成状态而不再演一次。必要的持物与站位锚点可以重复说明，执行动作不可重复。镜头一旦换序或合并，同步更新归属；一镜可以承担多个原文事项，不要求一句一镜。
   - 先按原话、语气和动作难度估算完整表演，再选可装下它的窗口。顺序发生的时间相加，真正同时发生的部分才重叠：边走边说可以共用窗口，等接稳才开口不能重叠；推送与接住同属一次交接，不把双方接触阶段各算一遍。开场辨位、必要反应和信息阅读时间只计一次，不能给每次切镜都额外加同一停顿。反应能否与对白重叠，以原文先后和画内实际可演为准，不因写了“同时”就认定成立。
   - 有试读、配音或实际视频时注明来源、正文版本和覆盖范围；没有时明确标为文本估计，给出能核对的发声、独占动作及重叠关系，不以固定字速或统一动作秒数冒充测量。时间不够先修窗口或边界，不加速、不删戏；不能用空动作或任意延长停留来凑数。计划只是核对依据，不新建资源，不成为第二套最终提示词外壳；不强制逐秒表、焦段数字或固定镜头数。
4. 确定独立生成分组：以镜头目的、完整表演预算与可衔接状态为依据，将可同次生成的镜头归组，再按实际型号与渠道能力选择合法整秒。约 5 秒是显存预算下的软偏好，不是上限、下限或凑满目标；合法时可以短于 5 秒，自然对白或动作放不下时可以超过并说明具体负载，不建立新的统一时长默认。只在内容、表演和连贯性同样成立的方案间优先更接近 5 秒的分组，不让偏好反过来决定删戏或空等。
   - 接触、交接、受力或尚未完成的动作，以及要求精确姿态和空间紧接的内容，优先放在同一次生成内；一次生成可含多个 Shot，换景别不是独立生成的理由。模型的最短生成时长不是内部每个 Shot 的下限，最长时长也不是要填满的配额。
   - 逐对比较相邻组：合并后若可自然演完、符合合法时长且没有必要的独立边界，就去掉无谓碎片；保留拆分时说明完整语义、动作阶段终点、信息揭示后的反应入口或实际生成预算等理由。不能为合并而赶对白或压缩复杂交接，也不能只为一行对白或一次切镜新建条目。
   - 在 prompt 外保留简短、可检查的分组理由与时间依据：各组覆盖哪些事项、主要发声／动作／反应如何相加或重叠、合计及估计或实测依据、为什么在这里结束并独立生成；可用短清单，不必另做表格或新资源。分组后将事项对应到片段／Shot，并复核动作唯一归属；相同的开场辨位或反应不要再加一次。
5. 明确每段的开场与结束状态，以及是否需要角色图、场景图、首尾帧或已有视频；读取实际输入，按可见内容分配参考用途，不凭标题猜图。缺素材不妨碍先写内容草稿，但必须说明缺口；不能把素材计划当成已绑定输入。
6. 按目标模型编写完整提示词，结构以 [视频提示词](video-prompts.md) 路由的专属附件为准，其他模型保留自身格式。H3 使用 [MiniMax H3 提示词](minimax-h3-prompts.md) 的中文正文、字段和切点语法，不混入通用 `Shot N（…）`、`【0-5s】`、`首帧：`、`结束状态：` 外壳，也不把计划、检查清单或待办塞进 prompt。
   - 用户明确要求 H3 全参考时，实际绑定参考就绪后按六字段成稿，逐张说明真实用途与保留关系；不能把身份图当首帧或把参考标题当画面证据。
   - 尚未实际绑定时，仍交完整可拍草稿，把“参考待绑定”、缺少哪些输入及尚未核实的外观放在 prompt 外的交付说明中；不伪造 input_id 或复制教学占位标签，不自动改成纯文生最终稿，不声称全参考生成条件齐备。待真实输入读取并绑定后，再补齐准确引用与参考分析。
   - 以上是明确全参考目标的就绪边界，不取消正常的无参考、首帧和首尾帧模式；这些模式仍按实际输入及对应附件编写。
7. 逐 Shot 核对可拍计划与成稿，并复核相邻分组：取景能否容纳关键动作及可见终点，切镜与运镜是否明确，声音与完整自然表演是否能在各自窗口及计划总长内完成；逐项对照原事件、逐字对白和动作归属，检查是否漏演、重演或无谓切碎。未通过先修正；要求的真实输入缺失时只交草稿与缺口，不报正式成稿完成。
8. 将制作内容写入 `/clips` 的 title、prompt、duration_ms 及已确定的配置，草稿状态与待办留在交付说明而非 prompt。创建后用返回 ID 继续操作，修订时保留已有 ID、ref 和未改内容，不另建普通画布节点。整集任务覆盖用户指定的整集，局部任务只改目标范围。
9. 回读本次实际保存结果，按下方写后核对重查每个 Shot、场次归属、顺序、总时长和相邻衔接。交付说明实际完成的分镜与尚未完成的素材、生成事项。

必须跨独立任务时，先选择可信的动作阶段终点、反应或重新交代空间的剪辑边界。真正要求边界画面严格接续时，评估真实型号与渠道的原生首帧／首尾帧能力，以实际采用视频的尾部状态作为下一段依据；计划终点不是已生成尾帧。可按「剧本工具使用规范」的制作画布附件获取持久尾帧资产，再按分镜与媒体节点附件绑定输入。

需要人物、场景与道具依据，又需要原生首尾帧约束时，可先合成并核对正式关键帧，再用于视频输入；已有准确帧直接复用，不要求每段额外生图。无法获得可靠边界约束时，按可独立成立的动作单元和可剪辑边界组织片段，说明接缝仍需后期检查。输入方式的能力与取舍见 [模型能力](model-capabilities.md)，生成后的真实接缝检查交给「媒体处理与剪辑」。

用户要求统一规格时，核对指定范围内实际保存的配置与提示词；仅修改文字不能据此断言视频已生成、结果已采用或质量已验收。

## 先把制作依赖排清楚

整场制作通常先做会被多段复用的人物、场景等参考，再按本段需要做占位与起始构图，最后生成动作。共用素材已有可用结果时直接复用；占位图对应具体分镜与动作起点，不先读旧占位图筛选复用。只改一条提示词时无需补做整套资产。

| 环节 | 要得到的具体结果 | 何时继续、何时返工 |
|---|---|---|
| 原文覆盖 | 关键动作、逐字对白、揭示顺序及各自承担的片段 | 核对遗漏、重复和提前泄露；剪辑表达可以变化，剧情事实不能暗改 |
| 共用视觉依据 | 符合 [人物参考固定格式](image-references.md) 的肖像＋三视图，以及场景布局、道具与状态 | 合格参考直接复用；已有单图只补缺失视图或整理排版。未齐全时说明缺口，不以正面图代替完成，不自动增加选角或未授权生成 |
| 占位图／预演（按需） | 按本分镜与动作起点，用导演台或 45° 斜俯视站位图表达空间关系 | 两种方式任选，不先读旧图筛选复用；按场次、分镜与用途命名，检查本次结果的朝向、距离、遮挡与轴线，不以静帧证明连续动作 |
| 首帧（按需） | 符合本镜实际景别与机位的起始画面 | 人物够不到物件、关键手部被挡或反打越轴时先调整；占位示意的俯视角与简化人形不直接作为正式首帧 |
| 本段提示词与输入 | 完整 Shot、时长、声音及相符的真实参考 | 有文字方案但未绑定输入时只算草稿；配置查询与写入按内置操作契约 |
| 已授权生成与核对 | 实际结果以及是否满足本镜的证据 | 如已有批量生成授权，优先验证最难且最有代表性的一段；通过后复用有效条件，不以一次成功保证整集 |
| 衔接与采用 | 相邻片段的实际起止状态、声音和采用结果 | 可修的局部问题优先定点处理；修改共享参考时重新检查受影响的下游片段 |

按依赖组织工作，不把制作顺序误当播放顺序：同一场景、同一光照和造型的图片可集中准备，最终仍按场次与分镜排序。共用图更新后，记录哪些分镜仍引用旧状态、哪些需要重看，不自动重生成全部内容。

### 并发与串行提交

是否同时提交按各段的实际输入和衔接要求判断，不按播放顺序判断。

- 可以并发：各段输入都已就绪且互不引用；共用同一套人物、场景参考或已有首帧不构成依赖。相邻段在反应、换景别等可剪辑边界拆开，接缝留给后期检查时，也可以并发。
- 必须串行：下一段要以上一段实际尾帧作为首帧，或要求姿态、空间严格接续；下一段的起点取决于上一段实际演到哪一步，例如动作是否完成、物件在谁手里；共用参考或首帧仍在生成或待核对；首次使用某个模型、参数或草稿配置时，先验证一段，通过后再放开并发。
- 串行时等上一段出结果，确认实际结尾，再按「剧本工具使用规范」截取尾帧并绑定为下一段输入后提交；不以计划终点提前提交下一段。
- 并发提交前向用户说明哪些段同时提交、相邻接缝靠什么衔接、哪些位置需要后期检查。

时长与重叠关系按上方拆分流程核算；跨独立生成尽量在完整语义或动作阶段后拆开，避免一句话的音色与节奏难以衔接。

完整工作示例见 [从原文到制作交付](scene-example.md)；不要求每次交付都使用同样数量的表格、素材或镜头。

## 写后核对

- 制片修改后回读实际片段，逐 Shot 对照原文事项与可拍计划：景别、机位与画内主体是否明确，起点、可见过程和终点是否成立；原动作、逐字对白及揭示顺序不遗漏、不重演。结束状态必须在该镜画内看得见；手部特写不能证明屏幕结果，需要屏幕可读取景或明确返回屏幕，游戏内容始终限于显示区域，不变成场内实体。
- 结合动作归属检查相邻片段：前段动作的后态是否成为后段的已完成状态，必要身份／持物锚点是否被误写成再次执行；两段能否合并而不损害表演，若仍独立生成，分组理由是否具体且必要。对白子串存在只能证明覆盖，不能证明拍法、唯一执行、先后关系或自然时长通过。
- 检查每次切镜的信息用途与递增切点、连续运镜的方向与停点，以及动作声、跨切声音和自然对白的窗口。H3 切点须严格落在总时长内；其他带区间格式须连续，总长与 duration_ms 及实际合法配置一致，不能只改一个字段。没有可信输出 fps 时不猜帧数，计划切点不等于实际视频已经精确执行。
- 核对场次归属、场内顺序与相邻起止状态，以及已有 ref 标签和真实输入用途。H3 格式不能夹带通用外壳或规划文字；明确全参考而引用未就绪，或拍法、时长、画内终点仍不成立时，修正或说明草稿与缺口，不报正式成稿完成。这是交付核对要求，不是自动运行的质量校验器。
- 换模型、段长或生成方式时，同时核对受影响的配置与提示词；仅改字段但正文仍沿用旧时长，不算完成。
- 区分“已写入片段”“参考待绑定”“待生成”和“实际结果已核对”。工具没有返回任务或视频结果时，不声称已生成、已采用或已导出；用户反馈失败时先定位配置、参考或内容问题，不把修改提示词当成重新提交成功。

## 看结果再返修

区分提交失败和画面不合要求。没有生成结果时先按操作契约核对任务状态、配置和输入；有结果时观察实际文件，不拿封面或提示词代替视频检查。按本段需要核对事件是否按顺序发生且只发生一次，主体与道具是否保持，空间与动作方向是否接得上，对白和声音是否属于正确人物与时刻，以及输出规格是否符合要求。只看静帧不能证明动作和口型正确，也不能证明没有声音。

为每个实际问题记录片段、发生时刻或帧、预期与观察差异，以及可以保留的部分，再按 [结果诊断与改写对照](troubleshooting.md) 选择修正。暂时无法定位原因时明确是待验证假设；不要同时改模型、参考、机位和风格，让下一次结果无法比较。是否重新提交、采用或扩大生成范围仍依用户授权与操作契约。
