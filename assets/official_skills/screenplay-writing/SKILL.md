# 剧本写作

将故事材料、用户粘贴内容、创作方向或已有稿件落实为本次需要的改编方案、分集大纲、场次正文、对白或审稿意见。用户说“把这些整理成剧本”时，直接走材料整理路线：先读实际内容，判断各段是小说叙述、梗概、对白、已有剧本或混合/残缺稿，保留有效部分，再选择合适的改编、分场和写场步骤；不要求用户先分类、另建来源小说或绑定来源作品。直接进入用户指定的环节；已确定的方案继续使用，不为改一句对白重做改编与分集，也不把审稿自动扩大成改稿。

## 确定任务与上下文

先确定目标作品、材料版本、本次范围和交付物。读取直接相关的原文、已有方案、人物与前后文，以当前实际稿件为准，不拿旧梗概代替正文；材料不全时说明已读范围、未读范围和结论限制。只整理场次时，不先要求整季规划、集数或时长。

用户已给足方向就执行。只有缺口会改变主角、核心选择、结局、核心关系或改编边界时才提问；普通措辞、动作呈现和局部节奏可直接处理。分集规划所需的集数与时长按对应附件处理，不自行假定。

原文事实、推断、候选改法与已确认方案分别表达。未获采用的构思不写成既定事实，局部修改不扩大到整季或原作。

只加载本次环节所需附件，执行对应环节前读完，不预读全部附件。使用 `<skill_resources>` 提供的 `reference-list` / `reference-get` 调用，`name` 使用「剧本写作」，`path` 原样复制附件目录中的路径；已在上下文中的附件无需重读。

混合任务按实际需要衔接：例如“把这段梗概和对白整理成剧本并写入”，先诊断材料、安排自然场次，再按场次写作落正文；不把每段都变成分析表，也不把整理自动扩大为整季规划。也可以“把这几章改成两集并写第一场”，先完成改编取舍与分集，再写指定场次。普通写作保留必要自检；用户要求专门审稿时才进入审稿流程，自检不声称独立复审。

## 写入与交付边界

- 读写剧本工作区前加载「剧本工具使用规范」对应附件，沿用其资源和操作契约。方案、大纲、场次梗概与正文各归其位，不把梗概当作正文，也不把整场 Markdown 塞进一个动作元素。
- 只讨论或展示文本时不建季、建集或修改原作；明确要求保存规划时，可按现有契约写入大纲、节拍或场次元数据，但不因规划默认创建正文或资料实体。要求正式写入正文时完成目标资源写入并回读核对，保留已有身份与未改内容。小说对白修订保留原有叙述格式。
- 正式整理交付真实结构化动作、人物提示和对白元素，不以名单、场次梗概或聊天草稿冒充正文。整理任务交代已有资料复用、获准补齐的资源和委派写手的写入责任；非正文资料仍须有明确任务授权，不默认绕过 Writer 的权限边界。写后核对实际写入范围、来源事件覆盖、遗漏与重复、对白归属、人物知情/位置/持物衔接和资料引用；长材料按实际批次报告完成、未写、待补与下一批起点。
- 只审查时给具体位置、证据、影响和修订目标，不直接改稿；获准审改时才修订指定范围并核对相邻上下文。缺少正文、原著或实测媒体时，不宣称对应部分已验证。
- 写后事实整理遵循主 Agent 既有流程与「故事连续性维护」，不在本技能另建自动审查或事实写入流水线；正文未写入的来源事件不当作当前故事事实。
- 目标时长、正文粗估与媒体实测分别报告。整集按整集范围核对，不用总字数、分镜计划时长或写入成功证明正文达标，不靠拖慢表演或重复内容凑时长。
- 分镜、视觉参考、视频提示词及生成结果返修使用「剧本制片」。写作阶段可以指出制作难点，但不因此自动出图、配音或生成视频；制片需改剧情时仍须遵循作者授权。
