# 场次写作与整理落稿

交付人物真正做了什么、说了什么以及造成的变化。场景的戏剧功能决定写法，格式和制作细节为内容服务。把用户材料整理成剧本时，正式写入必须落到真实场次和结构化正文，不以场次列表、Markdown 块或聊天草稿代替；讨论或预览不写入，明确保存规划只写获准的规划资源。

## 准备直接上下文

读取本次材料中相关的原文、已有场次完整正文元素、场次梗概或节拍、相关人物，以及衔接所需的前后场。续写时核对上一场的最后行动、知情状态和物件归属；已有剧本保留有效动作、对白和身份，当前正文优先，不以旧梗概、资料列表或旧状态替代。按批处理时标明本批写入范围和未覆盖位置。

委派前明确写入责任：调用方先准备必要的真实人物、地点和关键道具资料，或在任务中明确授权写手补齐；传递已有身份、目标资源和允许写入的范围，不因要求写正文就默认授权修改资料。复用前核对别名与身份，保留已有头像、四视图、照片和未改内容；缺少依赖且无补齐权限时，列出待补项交调用方处理，不编造引用。资料读写遵循「剧本工具使用规范」和当前资源契约。

用户已给足方向就开写。只有缺口会改变主角、核心选择、结局或改编边界时才提问；普通表达、动作呈现和局部节奏可直接处理。纯对白没有可靠说话人时保留不确定，不替材料发明事实。

## 写场

1. 明确这场为何存在、谁想得到什么、为什么难以得到，以及结束后什么会不同；以冲突推动的场景写出策略与反制，过渡、氛围、余波或仪式场景按实际作用组织，不硬造对手。
2. 从行动已经有压力的地方进入，保留理解所必需的空间信息；角色的下一步要回应刚发生的事，不能为了执行大纲而忽视现场变化。
3. 按材料证据把叙述和梗概转成可见动作、人物提示与可听对白；保留有效原稿，新增的连接和细节与原文事实分开。心理活动通过行为、对白、声画关系或符合既定形式的旁白表达，不把人物真实想法写成摄影机能直接拍到的事实。角色的知识、位置和持物必须能由前文或本场行动解释。
4. 场景达到预定结果后及时离开，保留必要留白；完成后读回实际写入范围，核对来源事件覆盖、遗漏、重复、顺序、对白归属和人物/地点/持物连续性。写后事实与关系维护由调用方按主 Agent 既有流程安排，遵守用户不委派或限制自动整理的要求，不把未写事件写入事实状态。

用户给定时长时，先安排本次范围内的行动、对白交锋与转折，再展开正文。整集要求按整集核对；委派部分场次时说明其负责范围，不把整集时长套给每一场。不得把时长要求换成固定字数指标。写完后依据实际正文核对内容容量，按连续表演段给出有依据的粗估区间，区分发声、独占动作与可重叠部分；不从目标倒推动作耗时，不把总字数、版面页数或分镜计划换算成正文时长。明显不足时展开被概括掉的交锋、行动、选择或后果，不靠增加描写字数、拖慢表演或承诺“后期补满”交差。写入成功或粗估接近目标，都不能单独证明时长达标。

场景因果、证据与选择的细节见 [场景手艺](scene-craft.md)。用户或作品智能体规则给出时长要求，或涉及多人动作、声音安排、AI 视频制作约束时，读取 [表演与制作约束](production-constraints.md)；有时长要求时，交付前按其中方法核对。对白是主要难点时读取 [对白修订](dialogue.md)，普通台词无需额外加载。

## 写入与局部修改

- 在剧本工作区读写前加载「剧本工具使用规范」，遵循其中完整的场次、`/elements`、`/cast`、分页、ID 和元素契约。场景标题由场次字段表达，正文写入动作、人物提示、对白等结构化元素；不发明 scene props 字段，不把整场 Markdown 塞进一个动作元素。
- 用户只要讨论或展示文本时按所需格式交付，不因此建季、建集或修改原作。明确保存规划时可写入已有大纲、节拍或场次元数据；用户要求正式写场时完成目标正文写入，不以梗概或聊天草稿代替。
- 局部修改只改对应元素；整场重写或重排先读齐并保留未改元素 ID。修改一个动作或一句台词，连读其前后节拍；检查位置、知情、称谓、说话人和持物仍一致。只改获授权范围，保留未改元素与已有身份。
- 写入成功不等于来源覆盖或时长达标，交付时分别说明实际范围、待补项和未验证部分；写后事实整理遵循主 Agent 既有流程，不在此另建自动审查或文件流水线。
